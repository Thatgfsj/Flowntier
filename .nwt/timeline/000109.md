event 000108 跑完了全部测试 + 修根因, 但还是最小化 — 只

## 审计: 还有哪些补丁活着

按 "修什么 → 为什么是补丁而不是根因" 整理:

### Patch A — `std::env::set_var` 在生产路径上 (unsafe since 1.84)
`crates/pipe-server/src/bin/flowntier-runtime.rs` (event 000091
fix #34):
```rust
unsafe { std::env::set_var("FLOWNTIER_HTTP_BRIDGE_TOKEN", &hex); }
```
这个调用是 **自指**: 同一个进程生成 token, 写进自己 env,
然后 `token_from_env()` 再读出来。MSRV 1.85 已经把
`std::env::set_var` 标 `unsafe`, 而且这污染了进程 env ——
测试套件并发跑 `#[tokio::test]` 时, 一个测试改了 env
var, 另一个测试读到的就是被改的。

**根因**: `run_http_bridge` API 不接受 token 参数,
只能从 env 读。

**修复**: event 000108 加了 `run_http_bridge_on_with_token
(listener, dispatcher, events, token_override)`。Sidecar
现在直接传 token 进去, 完全绕过 env var。生成 / 持久化
到 `.bridge_token` (供便携 HTML 前端读) 的逻辑保留,
但不再 mutate 进程 env。

### Patch B — `wipe_all_data` 的 taskkill 名字跟 spawn 不一致
`apps/desktop/src-tauri/src/lib.rs`:
- line 195 (spawn 前): `flowntier_runtime.exe` (下划线)
- line 1209 (wipe 前): `flowntier-runtime.exe` (连字符)

实际 `app.shell().sidecar("flowntier_runtime")` 用下划线。
连字符版 taskkill 永远返回 128 (no match), wipe_all_data
的"kill sidecar" 半步永远 no-op。

**根因**: 两处分别硬编码了同一个常量, 没共享。

**修复**: 提取 `const SIDECAR_IMAGE: &str = "flowntier_
runtime.exe"` 和 `fn kill_sidecar_silent() -> Option<i32>`
helper, 两个 caller 都用 helper。下划线 / 连字符的不一致
再也不可能发生。

### Patch C — 退出时 sidecar 还活着 (event 000098 一直挂着)
桌面进程退出时, spawned 的 `flowntier_runtime.exe` 没人
去 kill —— Tauri 的 `tauri::Builder::run` 默认是 "let it
drop", `child` handle 在 `tokio::spawn` 闭包里 move 走,
sidecar 没收到任何信号。结果:
- 下次启动 spawn 时, 上次的 sidecar 还活着 → pipe busy
- 整个 event 000083→000105 链都是因为这个 — 加 taskkill
  belt (000097)、修 first_pipe_instance (000103)、修 OS
  默认行为 (000105) 全是绕着同一个根因在转

**根因**: 没人调 `child.kill()`。

**修复**:
1. `SidecarHandle { pid: Option<u32> }` state, 在 spawn 成功
   时 `app.manage(SidecarHandle { pid: Some(child.pid()) })`
2. Tauri builder 加 `RunEvent::ExitRequested` handler:
   ```rust
   .run(|_app_handle, event| {
       if let tauri::RunEvent::ExitRequested { .. } = &event {
           graceful_kill_sidecar();
       }
   })
   ```
3. `graceful_kill_sidecar()` 先用 `taskkill /f /im`
   (兼容历史兜底), PID 留给后续 PR 用更精确的
   `OpenProcess + TerminateProcess` 升级。

这是 event 000098 提议的真正根因修复 —— 不需要再依赖
NSIS .onInit 的 taskkill belt (event 000097)。

### Patch D — 两套 panic hook, 文档说一套实际是另一套
- `tauri_core::logging::install_panic_hook` 写
  `<data_dir>/logs/panic-<ts>.log` (Tauri shell 进程)
- `flowntier-runtime.rs` 内联一个 `std::panic::set_hook`
  写 `~/Desktop/Flowntier.log` (sidecar 进程)

两边形态完全不同:
- tauri-core: eprintln + 完整 timestamped panic file
- sidecar: 裸 eprintln + 裸 OpenOptions append

`flowntier-runtime.rs` 把 hook 写在 binary entry 里, 不
在 `pipe_server::logs` 里 — 这导致:
1. 行为不一致 (Tauri shell panic 有独立文件, sidecar 没有)
2. 测试覆盖不到 (binary 函数不参与 `cargo test`)
3. 代码组织混乱 (subscriber 在 lib, hook 在 bin)

**根因**: panic hook 散落在两个地方, 没人集中管理。

**修复**:
1. 把 panic hook 从 `flowntier-runtime.rs` 挪到
   `pipe_server::logs::install_panic_hook(&Path)` lib 函数
2. Binary entry 改成:
   ```rust
   let _log_file = logs::init();
   if let Some(path) = &_log_file {
       logs::install_panic_hook(path);
   }
   ```
   Hook 现在跟 subscriber 用同一个 `log_file` 路径变量,
   真正的 single source of truth。
3. 加回归测试 `logs::tests::install_panic_hook_writes_to_path`:
   装 hook, `catch_unwind(|| panic!(...))`, 读文件验证
   marker `[flowntier-runtime] PANIC at <RFC3339>` 和
   panic message 都在。

## 防回归机制 (累积)

event 000108 + 000109 写下来的所有约束:

1. **改生产代码 → 必须重跑 cargo test --workspace --release**
2. **新防御层前 → 先写一个失败测试** (prod_pipe 三件套)
3. **process-global (env var, port, tmp, panic hook)**
   → unique 名 / override 参数 / 集中到 lib 函数
4. **token / secret / config → 参数传入, 不靠 env var**
5. **hardcoded 字符串常量 (sidecar image, log path)**
   → const + helper, 避免两处不一致
6. **子进程生命周期 → 用 RunEvent 主动管理, 不靠 "let it drop"**
7. **panic hook → 集中到 lib, 跟 subscriber 用同一路径变量**
