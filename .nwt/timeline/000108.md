### Stage 3 — Diagnose (按失败原因分类)

**类 A: 测试自己过期了 (生产协议改了, 测试没跟上)**
- `custom_provider_full_crud`: 还在用 v0.4.21 之前的字段
  (`name`, `default_model`, `api_key`), 实际 handler 现在要
  `id`, `display_name`, `models`, `api_key_env`
- `http_bridge_*`: event 000091 给 HTTP+SSE 桥加了 bearer
  token (000091 fix #34), 测试没设 token, 直接 401

**类 B: 代码 bug**
- `logs::write_read_clear_roundtrip`: `read_tail()` 永远读
  desktop 路径 (`resolve_log_path()`), 测试写到 tmp 路径,
  read_tail 看不到写入的内容, roundtrip 假阳性失败

**类 C: process-global env var (并发测试的根因)**
- 修 A 类 401 时, 第一次想 `std::env::set_var("FLOWNTIER_
  HTTP_BRIDGE_TOKEN", &token)`, 但 env var 是进程全局,
  多个 `#[tokio::test]` 并行跑就会互相覆盖 → 一个测试拿
  到另一个的 token → 间歇性 401
- 真正的修复: 给 `run_http_bridge_on` 加 `token_override:
  Option<String>` 参数, 测试直接传 token, **完全绕过
  env var**, 从根上消除竞争

### Stage 4 — Design
- 测试自己过期 → 改测试跟生产协议 (custom_provider 改两步,
  http_bridge 用 spawn_bridge 拿 token 后注入 header)
- 代码 bug → `read_tail` / `clear_log` 加 `path_override:
  Option<&Path>` 参数, 测试传 Some(&tmp_path), 生产传 None
- 并发 env var 竞争 → API 层加 `token_override`, 行为语义
  是 "override 优先, env 兜底", 测试永远走 override

## 防回归机制 (写下来, 下次别忘)

1. **改生产代码 → 必须重跑 `cargo test --workspace --release`**
   这是 event 000108 的核心结论。事件 000083-000105 全部
   失败都是因为没跑全测试。
2. **加新防御层前, 先写一个失败测试** — 防御是症状,
   测试是根因。
3. **测试并发跑时, 任何 process-global (env var, temp 文件,
   port) 都要用 unique 名 / override 参数** —
   `unique = format!("...-{}", nanos())` 是标准模式。
4. **token / secret 这类配置用参数传入, 不要靠 env var**
   — env var 是进程全局, 不适合跨测试隔离。
